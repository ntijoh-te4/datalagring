= NoSQL i praktiken — exempel med MongoDB

Det här utkastet utvidgar nuvarande NoSQL-kapitel med ett konkret exempel: https://www.mongodb.com/[MongoDB], som är en av de mest spridda dokument­databaserna.

== Dokumentmodellen

I MongoDB lagras data inte i tabeller med rader, utan i _collections_ (samlingar) av _documents_ (dokument). Ett dokument är i praktiken ett JSON-objekt (egentligen BSON — en binär variant).

[source,json]
----
// Ett dokument i collection 'students'
{
  "_id": "65f1a2b3c4d5e6f7a8b9c0d1",
  "first_name": "Karl-Gustaf",
  "last_name":  "Sjöblom",
  "class": "TE21A",
  "grades": [ <1>
    { "course": "EN7", "grade": "B" },
    { "course": "MA4", "grade": "A" }
  ]
}
----
<1> Lägg märke till att betygen är _inbäddade_ direkt i student-dokumentet — i en relationsdatabas hade detta varit en separat tabell.

Det är ett medvetet val: i MongoDB optimerar man ofta för _läsmönster_ snarare än för normalisering. Om man nästan alltid hämtar en student tillsammans med dess betyg är det effektivt att ha dem i samma dokument.

== CRUD i MongoDB

För varje vanlig SQL-operation finns en MongoDB-motsvarighet.

.SQL — skapa
[source,sql]
----
INSERT INTO students (first_name, class) VALUES ('Anna', 'TE21A');
----

.MongoDB — skapa
[source,javascript]
----
db.students.insertOne({ first_name: "Anna", class: "TE21A" })
----

.SQL — läsa
[source,sql]
----
SELECT * FROM students WHERE class = 'TE21A';
----

.MongoDB — läsa
[source,javascript]
----
db.students.find({ class: "TE21A" })
----

.SQL — uppdatera
[source,sql]
----
UPDATE students SET class = 'TE21B' WHERE first_name = 'Anna';
----

.MongoDB — uppdatera
[source,javascript]
----
db.students.updateOne(
  { first_name: "Anna" },
  { $set: { class: "TE21B" } }
)
----

.SQL — radera
[source,sql]
----
DELETE FROM students WHERE first_name = 'Anna';
----

.MongoDB — radera
[source,javascript]
----
db.students.deleteOne({ first_name: "Anna" })
----

== Index och sökning

MongoDB stödjer index på samma sätt som relationsdatabaser:

[source,javascript]
----
db.students.createIndex({ class: 1 }) <1>
db.students.createIndex({ "grades.course": 1 }) <2>
----
<1> Index på fältet `class` (1 = stigande, -1 = fallande).
<2> Index på ett _inbäddat_ fält — något som inte är möjligt i en relationsdatabas utan att normalisera ut det till en egen tabell.

== Aggregering

Istället för `GROUP BY` har MongoDB en _aggregation pipeline_ — en sekvens av bearbetningssteg.

[source,javascript]
----
db.orders.aggregate([
  { $match: { status: "completed" } },             <1>
  { $group: { _id: "$customer_id",                 <2>
              total: { $sum: "$amount" } } },
  { $sort:  { total: -1 } },                       <3>
  { $limit: 10 }
])
----
<1> Filtrera (motsvarar `WHERE`).
<2> Gruppera och summera (motsvarar `GROUP BY` + `SUM`).
<3> Sortera fallande (motsvarar `ORDER BY ... DESC`).

== När ska man välja MongoDB?

Bra användningsområden:

- *Innehåll med variabel struktur* — t.ex. produktkataloger där olika produkter har olika attribut.
- *Hierarkisk data* — kommentarer, bloggposter med taggar, kapslade konfigurationer.
- *Snabba prototyper* — ingen schema-design upfront krävs.
- *Hög skrivlast* med behov av horisontell skalning.

Mindre bra användnings­områden:

- *Data med tydliga relationer* — gå hellre relationellt.
- *Komplexa transaktioner över flera dokument*.
- *Affärs­kritisk data* där ACID är ett krav.
